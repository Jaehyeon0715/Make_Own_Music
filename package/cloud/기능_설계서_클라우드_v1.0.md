## 1. 기능 개요

기획 입력 → 트랙 자동 생성 → DAW 편집 → 믹스 다운로드. 무거운 연산은 단일 워커 큐로 직렬화.
전 연산은 **클라우드 GPU**에서 수행, 사용자 기기는 얇은 클라이언트(브라우저).

| 영역 | 핵심 기능 |
|------|----------|
| 기획 | 장르·분위기·BPM·Key·길이·추가지시 → AI 트랙 목록 + 캡션 |
| 생성 | 전체 생성(순차) / 스템 분리 생성(곡 1개 → Demucs) |
| 편집 | 재생성 · Repaint · 볼륨 · 잠금/오버라이드 |
| 믹스 | pydub 볼륨 믹싱 → WAV/MP3, 버전 관리(최대 10) |
| 세션 | 다른 기기 재접속 복원, TTL 24h 정리 |
| Provider | Claude/OpenAI(GPU 절감) 또는 Ollama(GPU) |

> 코드 호환 근거: 트랙 생성은 전부 `ACESTEP_URL` HTTP 호출(`ace_client.py:12`).
> `DB_PATH`·`OUTPUTS_DIR`·`CORS_ORIGINS`·`API_KEY`·`AI_PROVIDER` 모두 env 오버라이드(`config.py`) → **코드 무수정 전환**.

| 3 | POST | `/plan` | AI 기획 → 세션·트랙 | 동기 | **필수** |
| 4 | GET | `/session/{id}` | 세션 복원(타 기기) | — | **필수** |
| 5 | POST | `/generate/all` | 전체 생성 | **HEAVY=0** | **필수** |

| 7 | POST | `/generate/track/{id}/{order}` | 단일 재생성 | LIGHT=1 | **필수** |

## 3. 핵심 기능 상세

### 3-1. 트랙 기획 (`/plan`)
- 입력·캡션 규칙은 로컬과 동일.
- `AI_PROVIDER=claude/openai/gemini` → 기획 단계 외부 API 위임 → **Ollama GPU 불요(비용↓)**.
- `AI_PROVIDER=ollama` → Ollama 컨테이너+GPU(VRAM·비용↑).
- API 키는 시크릿 매니저 주입(이미지·리포 하드코딩 금지, 기획 §6-4).

### 3-2. 전체 생성 / 스템 분리 (HEAVY)
- `ACESTEP_URL=http://acestep:8001`(내부 DNS) 또는 모델 A면 proxy URL.
- ⚠️ 타임아웃: ACE-Step CPU 폴백 매우 김(`ACESTEP_CLIENT_TIMEOUT` 기본 1800s, `ace_client.py:14`).
  **Caddy SSE 타임아웃 ≥ 1800s** 보장 필요(기본 60s면 장시간 생성 끊김, 기획 §6-9).

### 3-3. 편집 (LIGHT) — 로컬과 동일 로직
| 기능 | 경로 |
|------|------|
| 재생성 | `/generate/track/{id}/{order}` |
| Repaint | `/repaint` |
| 볼륨 | `.../volume` |
| 잠금 | `.../lock` |

### 3-4. 믹스 / 세션 / Provider
- 믹스: `MAX_MIX_VERSIONS=10`, oldest 삭제. outputs는 볼륨/오브젝트 스토리지.
- 세션: **다른 기기/브라우저 재접속 → `/session/{id}` 복원**(모바일 백그라운드 끊김 대응).
- Provider 교체: 큐 경유. GPU 비용에 직결(외부 API ↔ Ollama).

## 4. 큐 / 동시성

```
브라우저 → Caddy(443) → FastAPI :8080(내부) → PriorityQueue (단일 워커) → ACE-Step:8001 / Demucs / mixer
```

| 우선순위 | 값 | 작업 | 순서 |
|---------|----|------|------|
| HEAVY | 0 | 전체 생성, 스템 분리 | **먼저** |
| LIGHT | 1 | 재생성, Repaint, Provider 교체 | 나중 |

> 단일 워커 = 클라우드 GPU VRAM 직렬. 16GB+ 권장(Ollama 포함 24GB, 기획 §9).
> SQLite WAL 단일 라이터 → **단일 백엔드 인스턴스 유지**(수평 확장 비목표).

## 5. 클라우드 배포 특성 (구동 모델)

| 모델 | 구성 | 적합 |
|------|------|------|
| **A** | ACE-Step만 클라우드, 백엔드 로컬, `ACESTEP_URL`만 원격 | 최소 변경 시작 |
| **B** | 전체 스택 1박스(ACE-Step+Demucs+backend+Caddy) | 자주·빠른 응답 |
| **C** | 서버리스 GPU(요청 시 웜업) | 간헐 사용·비용 최소 |

| 항목 | 값 | 근거 |
|------|-----|------|
| 접속 | `https://<도메인>` (HTTPS 필수) | 기획 §1 |
| 인증 | **`API_KEY` 필수** + proxy 이중화 | 기획 §6-2 |
| 내부 서비스 | 8080·8001·11434 외부 비공개 | 기획 §6-2 |
| CORS | `CORS_ORIGINS=https://<도메인>` (와일드카드 금지) | 기획 §6-2 |
| 레이트 리밋 | proxy IP/키별 제한(비용·남용 방어) | 기획 §6-2 |
| 비용 | GPU 시간당(B)/요청당(C), 유휴 자동 정지 | 기획 §6-5 |

## 6. 비용 · 보안 기능 요점

| 측면 | 대응 |
|------|------|
| GPU 비용 폭증 | 유휴 자동 정지/서버리스(C), 레이트 리밋, 예산 알람 |
| 무인증 노출 | `API_KEY` 필수 + proxy 인증, 401 차단 검증 |
| 평문 HTTP | Caddy 자동 HTTPS, HTTP→HTTPS 리다이렉트 |
| SSE 타임아웃 | proxy 타임아웃 ≥ 1800s, 세션 복원으로 결과 회수 |
| cold start(C) | "웜업 중" UX, 최소 1 웜 인스턴스 옵션 |
| 데이터 소실 | 영속 볼륨/오브젝트, 정기 백업 |
| API 키 유출 | 시크릿 매니저, env 주입, 키 로테이션 |

## 7. 에러 처리 (로컬 공통 + 클라우드 추가)

| 상황 | 코드 | 처리 |
|------|------|------|
| Provider 실패 | 502 | `AI provider failed` |
| DB 실패 | 500 | `DB error` |
| 세션 없음 | 404 | `Session not found` |
| Repaint 구간 오류 | 400 | `end_sec must be greater than start_sec` |
| **API 키 없음/불일치** | **401** | `Invalid API key` (무인증 차단) |
| 생성 부분/전부 실패 | SSE | `done.status=partial/error` |
